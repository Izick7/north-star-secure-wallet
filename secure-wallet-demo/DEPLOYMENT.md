# Deployment checklist

This repository is designed for local demonstration first.

## Recommended deployment shape
- PostgreSQL: managed PostgreSQL with TLS and automated backups.
- Backend: Render web service using `backend/` as root directory, build command `npm install && npm run db:migrate`, start command `npm start`.
- Frontend: Vercel project using `frontend/` as root directory, build command `npm install && npm run build`, output directory `dist`.

## Before deploying
1. Use a strong unique `JWT_SECRET` (32+ characters; ideally generated by a password manager).
2. Set `NODE_ENV=production`, `COOKIE_SECURE=true`, `DATABASE_SSL=true` if your database provider requires TLS.
3. Set `FRONTEND_ORIGIN` to the exact HTTPS Vercel domain.
4. Set `DATABASE_URL` to the managed database URL. Restrict network access where supported.
5. Ensure frontend and API share a compatible cookie site. If frontend and backend are on different sites, SameSite=Lax cookies may not be sent; use a same-site custom domain/reverse proxy rather than casually weakening cookie policy.
6. Disable demo seeding (`SEED_DEMO=false`) and remove or rotate demo accounts for any publicly reachable deployment.
7. Configure database backups, alerts, logs without secrets/PII, and test restore procedures.
8. Run tests against a dedicated test database.
9. Verify HTTPS, origin handling, login/logout, session expiry, duplicate transfer requests, insufficient funds, concurrent requests, and cross-user access.
10. Do not expose a publicly deployed demo with demo credentials and seeded balances enabled.

## Deployment caveat
This code is a learning project and has not been independently audited. Do not use it for real funds. For real money, integrate a licensed payment provider and get legal/compliance and professional security review.
